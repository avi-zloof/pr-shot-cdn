INT-1236 Orchestration upgrade Atrium Core

Cast → Tape

An upgrade to how Atrium deliveries are planned and closed — not a product UI release. This note is only about the orchestration flow.

Who should read this: anyone who runs or reviews agent deliveries — orchestrators, developers, validators, auditors, and teammates who need to understand why a run named a cast and left a tape. If you only care about app features, you can skip this.
Flow Plan → Cast → Spawn → … → Tape → Audit
PR = what · Tape = how

What changed

The shared orchestration path now makes two phases explicit: Cast (who runs the ticket) and Tape (how the run actually went). Thin tickets can cast {Dev} only; parity and delivery-risk tickets cast more roles. Auditor may require Tape before merge — Auditor does not write the Tape.

Plan→Cast→Spawn→…→Tape→Audit

What is Cast?

Cast is the planner output after Plan and before anyone is spawned. The orchestrator names the agent team for this ticket. It is not optional ceremony — each role must own a failable check, not opinions.

Dev

Implements in the feature worktree. Always present for repo work.

Validator

Gap-check against a source of truth (parity, contracts, Me = token owner). Use when the ticket mirrors another surface.

Auditor

Delivery gate only: branch, UI evidence, tests. Not the same as Validator.

Security / Visual

Only when the ticket needs them — not default cast members.

Default for parity tickets (iOS similar to web, Me/Project scopes, shared API): Cast: Dev + Validator, then Auditor.

What is Tape?

Tape is the orchestrator’s last story phase — a compact run record of how the delivery happened. The product PR describes what shipped; the Tape describes the path: cast, attempts, gates, and outcome.

  • Written after the PR is ready (before or after Auditor)
  • Artifact: docs/runs/<ISSUE_KEY>-tape.md and/or a short chat summary
  • Auditor may require Tape presence; Auditor does not author Tape
Plan ✓ → Cast{Dev,Validator} → Attempt1 … ✗ → Attempt2 … ✓ → Gate ✓ → Out

Why it matters

  • Clear ownership — you know who was cast before work starts
  • Recoverable history — Tape reconstructs the run without mining chat
  • Honest gates — Auditor checks delivery; Validator checks truth; neither blurs into the other
